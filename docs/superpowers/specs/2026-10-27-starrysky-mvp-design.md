## 1. 这是什么东西，为什么做

一个 Windows 桌面 3D 建模工具的最小可行产品，显示名 **星空**，代码里叫 **StarDream**（中文做程序集名会在部分工具链上出编码问题，显示名用中文，命名空间用英文）。

**界面参考 Blender**：分区、面板、视口布局。
**操作参考 Maya**：相机导航、快捷键、框选习惯。

观感用 WinUI 3 的 Fluent / 亚克力 / 深色，3D 视口是自己写的 Direct3D 11 渲染器嵌在 `SwapChainPanel` 里。

和普通"3D 查看器"的区别在于它是一个**建模器**：能进编辑模式改点线面，能把结果导出成 FBX 给虚幻引擎用。

用户偏好来源（`C:\Users\Star\Desktop\界面库.txt`）：喜欢亚克力（Acrylic），默认深色。

## 2. 目标 / 非目标 / 反目标

### 目标
- 打开就能在 1 秒内进入可操作的 3D 视口，帧率稳定 60fps（1080p，单场景几万三角形）。
- 完成一次真正的建模闭环：加基本体 → 进编辑模式改点/线/面 → 挤出成型 → 保存 → 关掉 → 重开还一模一样 → 导出 FBX。
- 导出的 FBX **以虚幻引擎为第一验收对象**：UE 5.8 无头导入无错误，朝向、尺寸、法线正确。
- 次要验收：同一文件在 Maya 2027 和 Blender 5.2.3 里打开，形状一致。

### 非目标（这个 MVP 不做）
- 倒角、环切、布尔、镜像、焊接、桥接等高级网格操作。
- 修改器栈、UV 展开、材质节点、贴图。
- 动画、骨骼、物理、粒子。
- 脚本、插件、Python 控制台。
- 多文档标签页、撤销/重做。
- 导入（只导出 FBX，不导入）。
- 多选对象、成组、父子层级。

### 反目标（功能都做齐了，这些也算失败）
- 视口拖动时明显掉帧或撕裂。
- 目标机器上双击 exe 打不开。
- WinUI 原生控件和视口风格割裂（视口亮的、控件暗的）。
- 保存的文件打不开，或打开后物体位置变了。
- 导出的 FBX 在 UE 里是空的、散架的、朝向反的、或者法线全黑。

## 5. 我替用户做的决定（可以推翻）

| 决策 | 我的选择 | 理由 |
|---|---|---|
| 语言 | C# | WinUI 3 的 C# 路径省掉大量 WinRT 样板 |
| 渲染 | 自写 D3D11（Vortice 绑定） | 官方 `SwapChainPanel` 通道，不需要挂子窗口 hack |
| 部署 | 非打包 + Windows App SDK 自包含 + .NET 自包含发布 | 目标机器不需要装 VS/SDK/运行时 |
| 拾取 | CPU 求交 | 场景规模小，比 GPU ID buffer 简单且无兼容坑 |
| 场景文件 | JSON，参数或顶点二选一 | 编辑过的网格已无法由参数还原 |
| FBX 写法 | 用 GitHub 现成的 **ufbx-write**（MIT / 公有领域），输出二进制 FBX 7400 | 许可干净、C ABI 好 P/Invoke，比自己写格式靠谱 |
| 撤销/重做 | 不做，改用自动保存草稿兜底 | 撤销会给每个操作加一层设计，不是 MVP 验收项 |
| 网格数据结构 | 多边形面表 + 派生邻接 | 不做半边结构；点线面编辑用派生边表 + 面表足够 |
| 法线 | 逐角法线 + 30° 自动平滑 | 立方体要硬边、球要平滑，一套规则通吃 |

### 8.2 网格数据结构

```csharp
class Mesh {
    List<Vector3> Positions;      // 顶点
    List<Face> Faces;             // Face = int[] 顶点索引，逆时针
    // 派生缓存（拓扑变化时重建）
    List<Edge> Edges;             // 由面表推导，无序顶点对去重
    List<int[]> Triangles;        // 渲染与拾取用的扇形三角化
    Vector3[] FaceNormals;
    Vector3[] CornerNormals;      // 逐角法线，长度 = 所有面的顶点数之和
}
```

**法线规则（决定观感，写死）**：
- 先算面法线；对每个顶点，把相邻面按法线夹角聚类，夹角 ≤ 30° 视为同一平滑组。
- 同一平滑组内的角共享一条法线；不同组之间是硬边。
- 立方体因此全硬边、球体全平滑，一套规则通吃。
- 渲染时按「(顶点, 平滑组)」拆分成独立顶点送进顶点缓冲。
- 导出的 FBX 用 `ByPolygonVertex / Direct`，一条一条角法线写出去。

### 8.3 渲染

- D3D11，`B8G8R8A8_UNorm` 交换链，`D24_UNorm_S8_UInt` 深度，双缓冲，vsync on。
- 用 `Vortice.WinUI` 的 `ISwapChainPanelNative.SetSwapChain` 绑定到 `SwapChainPanel`。
- 交换链尺寸 = 面板实际像素 × `CompositionScaleX/Y`。
- 一帧顺序：
  1. 清屏（深灰蓝，与界面同色系）
  2. 地面网格 + 坐标轴
  3. 可见物体（Lambert + 半球环境光）
  4. 选中物体描边（背面外扩纯色）
  5. （编辑模式）当前网格的半透明实体
  6. （编辑模式）边线（深度偏移）
  7. （编辑模式）顶点小方块（实例化，屏幕尺寸恒定）
  8. 选中元素高亮（面填充橙色 / 边线橙色 / 点橙色）
  9. gizmo（关闭深度写入，永远最上层）
- 编辑模式的点用**实例化小四边形**画，不用 `POINTLIST`（D3D11 点大小固定 1px）。
- HLSL 放 `.hlsl` 文件，嵌入资源，运行时用 `D3DCompiler` 编译一次并缓存。

### 8.4 相机与变换约定（写死，不许各模块各搞一套）

- **右手系，Y 轴向上**，单位 1 = 1 米。
- 欧拉角：**XYZ 外旋**，内部按 `R = Rz * Ry * Rx` 组合，存储单位为度，范围 ±180。
- 相机：环绕相机（目标点、距离、偏航、俯仰），俯仰夹在 ±89°。透视，FOV 45°，近 0.1，远 500。
- **gizmo 轴**：
  - 移动、旋转用**世界轴**。
  - **缩放用物体局部轴**。理由：旋转过的物体沿世界轴缩放会产生剪切，而 `position/rotation/scale` 存不下剪切；沿局部轴缩放才和存档格式自洽。
- 基本体出生位置：立方体/球/圆柱的轴心在几何中心，落位时让**底面贴地**（y = 半高）；平面放在 y = 0。

### 8.5 拾取

- 屏幕点 → 反投影世界射线。
- 对象模式：遍历可见物体，射线与其三角形求交（Möller–Trumbore），取最近。
- 元素拾取：
  - 点：所有顶点投影到屏幕，取 8px 内最近的那个（带深度排序）。
  - 线：所有边投影为屏幕线段，取 6px 内最近。
  - 面：对当前网格做射线-三角形求交。
- 框选：屏幕矩形与投影后的点/边/面中心求交。
- 不做加速结构，万级三角形暴力够用。

### 8.6 Gizmo

- 移动（三箭头 + 中心）、旋转（三圆环）、缩放（三轴方块 + 中心）。
- 命中检测在屏幕空间：轴/环采样成折线投影，算鼠标到折线的像素距离，< 8px 命中。
- 拖动：移动/缩放 → 射线与轴所在平面求交取轴分量；旋转 → 射线与环平面求交算角度差。
- 编辑模式下 gizmo 作用在选中元素的**中心**，旋转/缩放围绕该中心。

### 8.7 编辑模式

- 进入：F8。只对当前选中的**单个**物体生效，其它物体灰显且不可选。
- 点/线/面模式互斥（F9/F10/F11），切换时清空选择。

**删除**：
- 面模式：删掉选中的面，再清理不再被任何面引用的孤立顶点。
- 点模式：删掉引用该点的所有面，再清理孤立点。
- 线模式：删掉共享该边的面。

**挤出（Ctrl+E，仅面模式）**：
1. 把选中面按共享边拆成**连通块**。
2. 每个块单独处理：
   - 块内没有边界边（即闭合网格，比如整个立方体）→ 跳过，状态栏提示「闭合选区没有可挤出的边界」。
   - 块的法线**面积加权平均**长度 < 0.1 → 跳过，提示「选中面的法线互相抵消」。
3. 复制该块的顶点；块内的面改指向新顶点；每条边界边补一个四边形侧面。
4. 新顶点沿该块的平均法线平移 **0.2 m**（固定值，随后可用移动 gizmo 微调）。
5. 选择切换到新生成的顶盖面，方便连续挤出。
- 非面模式下按 Ctrl+E 只提示，不做事。
- 挤出**不做**孤立顶点清理（旧顶点仍连着侧面）。

**参数冲突规则**：基本体一旦被编辑（顶点被改动过），就从"参数化"变成"烘焙"，Properties 里的参数区变为只读并标注"已编辑"。

### 8.8 FBX 导出（游戏流程 / UE 优先）

**用现成的库**：[ufbx-write](https://github.com/ufbx/ufbx-write)，MIT / 公有领域双许可，单文件 C99，纯 C ABI。**锁定一个 commit**，不跟 `main`。

接入：
- `native/StarDream.FbxNative` 把 `ufbx_write.c/.h` 编成 x64 DLL（MSVC）。
- `StarDream.Core/Export` 写一层薄 P/Invoke，对上层暴露 `FbxExporter.Export(doc, path, profile)`。

**导出配置**：

| 项 | 值 | 说明 |
|---|---|---|
| 格式 | 二进制 FBX，version 7400 | UE 5.x 完全支持 |
| 坐标系 | right = +X, up = +Y, front = −Z | 标准 Y-up 右手系；UE 勾「Convert Scene」自动转 Z-up 左手 |
| 单位 | `unit_scale_factor = 100` | 场景 1 单位 = 1 米，FBX 里按厘米 |
| 节点 | 每对象一个 node，带 T/R/S | 几何在**局部空间**，枢轴在物体原点 |
| 面 | 三角化 | 游戏流程要三角面 |
| 法线 | 每多边形顶点，Direct | 用 8.2 的逐角法线 |
| UV | UV0，盒式投影 | 缺 UV 时 UE 会报警并给退化 UV |
| 材质 | 每对象一个 Phong，DiffuseColor = 对象颜色 | UE 会建出对应材质槽 |
| 不导出 | 相机、灯光、gizmo、地面网格 | 只要模型 |

**UE 导入设置**（写进 README）：Convert Scene ✓、Import Translation/Rotation/Scale ✓、Combine Meshes ✗、Generate Lightmap UVs ✓、Normals = Import。

**验收环境（三个都已确认可用）**：
1. **UE 5.8 无头导入**（第一验收）：`E:\UE_5.8\Engine\Binaries\Win64\UnrealEditor-Cmd.exe` 跑 Python `AssetImportTask`，断言资产存在、三角形数一致、包围盒误差 < 0.1 cm、朝向没翻。
2. **Blender 5.2.3 无头导入**：`E:\3D\Blender\blender.exe -b --python`，导入后比对顶点数、三角形数、包围盒。
3. **Maya 2027 人工确认**：至少一次，导出→打开→看形状。

Unity 和 3ds Max 机器上没有，不作为本期验收项。

**备选**：若 ufbx-write 的输出 UE 不认，退回自己写 ASCII FBX 7.4（不引 Autodesk SDK）。备选不预先实现。

### 8.10 文件交互、脏状态与失败路径

- `Ctrl+S / Ctrl+O` 用系统 `FileSavePicker` / `FileOpenPicker`，非打包 WinUI 3 里必须先 `InitializeWithWindow.Initialize(picker, hwnd)`。
- 保存路径记在文档状态里，之后再 Ctrl+S 直接覆盖，不弹框。
- **脏的定义**：只有场景内容变化才算脏（对象增删、变换、颜色、显隐、拓扑、参数）。相机、选择、当前工具、当前模式**都不算**。
- 相机在显式保存时写入文件；打开时恢复到**保存时**的相机。
- 新建/打开/关窗时若有未保存修改，弹 `ContentDialog`：保存 / 不保存 / 取消。
  - 选「保存」但 `FileSavePicker` 被取消，或写盘失败 → **原操作中止**，窗口留着，文档仍然是脏的，状态栏报错。
  - 选「取消」→ 什么都不变。
- 关窗拦截用 `AppWindow.Closing` + 延迟的异步对话框（`Window.Closed` 拦不住）。
- **系统关机/注销**：不加拦截，直接关闭（异步对话框挡不住关机），文档注明这是已知取舍。

### 8.11 自动保存

- 有未保存修改时，每 30 秒写一次 `%LOCALAPPDATA%\StarDream\autosave.stardream`。
- 正常保存后删除草稿。
- 启动时若发现草稿比上次保存新，弹一次「恢复上次内容？」。
- 没有撤销，这条是唯一的误操作兜底。

### 8.12 输入

- `SwapChainPanel` 挂 `PointerPressed / Moved / Released / WheelChanged`。
- 键位判断用 `PointerPoint.Properties` 与 `KeyModifiers`。
- 快捷键用 `KeyboardAccelerator` 挂窗口。

### 8.13 构建与分发

- `WindowsPackageType=None`，`WindowsAppSDKSelfContained=true`。
- 目标框架：`net8.0-windows10.0.26100.0`；若最新 Windows App SDK 要求更高则上 `net10.0-windows…`，实现时按 NuGet 实际支持锁定。
- 依赖锁定精确版本：`Microsoft.WindowsAppSDK`、`Vortice.Direct3D11`、`Vortice.WinUI`、`Vortice.D3DCompiler`、`CommunityToolkit.WinUI.Controls.Sizers`。
- 开发时 `dotnet run --project src/StarDream.App`。
- 发布：`dotnet publish -c Release -r win-x64 --self-contained true`，产物是可直接双击的目录；目标机器只需 VC++ 运行库。

## 9. 关键风险与应对

| 风险 | 应对 |
|---|---|
| `ISwapChainPanelNative` 与最新 Windows App SDK 不兼容 | M1 冒烟测试；不行退回 1.6（机器已装运行时） |
| 高 DPI 交换链尺寸算错导致模糊 | M1 用 `CompositionScaleX/Y` 验证 |
| ufbx-write 是 WIP，或 UE 不认它的输出 | 锁 commit；**M3.5 提前做 FBX 尖刺**；不行退回自写 ASCII FBX |
| 逐角法线 + 顶点拆分改动面大 | M3 就按逐角法线实现，不留到后面 |
| 挤出在非流形/闭合选区上出问题 | 按 8.7 的连通块 + 拒绝规则；M8 加单测 |
| 发布产物在别的机器打不开 | **M1.5 提前做发布冒烟**；**本机没有干净 Windows 11 环境**，所以只能做依赖检查（确认不依赖 VS/SDK 私有 dll）+ 目录搬移后双击，属于"部分验证"，文档里如实标注 |
| 无撤销导致误操作丢工作 | 自动保存草稿（8.11） |
